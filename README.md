# Digital Payment Insight

An end-to-end data science project for exploring digital payment transactions, engineering behavioural features, and training a baseline machine-learning model to prioritize transactions for manual review.

> **Data and model disclaimer:** This project uses synthetic data. The target is a simulated review-priority label, not confirmed fraud. Reported model metrics describe performance against synthetic labels only and must not be interpreted as real-world fraud-detection performance.

## Project overview

The pipeline demonstrates a practical data-science workflow:

1. Generate synthetic transaction and reference datasets.
2. Validate records, remove duplicate transaction IDs, standardize inconsistent values, and handle missing data.
3. Join transaction data with customer, device, merchant, and alert information.
4. Explore transaction amounts, time patterns, merchant categories, regions, and device behaviour.
5. Engineer behavioural features for modelling.
6. Train a Random Forest classifier using a stratified train/test split.
7. Evaluate the model and export charts, metrics, an Excel analysis workbook, and a PowerPoint summary.

## Quick start

### 1. Clone the repository

```bash
git clone https://github.com/Neemasree/-DIGITAL-PAYMENT-INSIGHT.git
cd -DIGITAL-PAYMENT-INSIGHT
```

In **Windows PowerShell**, if the folder name beginning with a hyphen causes a parsing issue, use:

```powershell
Set-Location -LiteralPath '.\-DIGITAL-PAYMENT-INSIGHT'
```

### 2. Create and activate a virtual environment

**Windows PowerShell**
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

**macOS / Linux**
```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 4. Run the pipeline

Run from the repository root:

```bash
python src/build_project.py
```

The script generates the project's datasets and analysis deliverables. Check the terminal output and generated files to confirm the run completed successfully.

## Notebook

Open `notebooks/digital_payment_eda.ipynb` in Jupyter or upload it to [Google Colab](https://colab.research.google.com/). If the notebook expects files generated by the pipeline, run the pipeline first or update the notebook's data path to match your environment.

## Model evaluation

The pipeline reports standard classification metrics, including accuracy, precision, recall, F1-score, and ROC-AUC where applicable. For a review-priority use case, precision and recall should be interpreted together: false positives increase manual-review workload, while false negatives can leave unusual transactions unreviewed.

Use the metrics generated by your own run as the source of truth. Results can vary with data-generation settings, preprocessing, and model configuration.

## Responsible use and limitations

- All records and labels are synthetic and intended for learning and demonstration.
- The model does not establish whether a transaction is fraudulent.
- Do not use this prototype to decline, block, or otherwise make decisions about real payments.
- A production system would require authorized real data, verified outcomes, data-leakage checks, privacy and fairness review, threshold validation, monitoring, and human oversight.
